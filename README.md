# combat


خواندن متغیر محیطی زمان بیلد option_env!("MOBA_SERVER_ADDR")؛ اگر هنگام بیلد مقداردهی شده باشد، مستقیماً به عنوان IP و پورت مقصد در باینری کلاینت ثبت می‌شود.

اگر moba_client.exe بدون آرگومان خط فرمان (با دابل‌کلیک) اجرا شود، یک client_id یکتا از زمان سیستم تولید می‌شود تا دو بازیکن هم‌زمان روی یک client_id تکراری رد نشوند.

مراحل اجرا در سرور اوبونتو و بیلد کلاینت:
روی سرور اوبونتو (/opt/combat/moba_server/config.ron):

server_bind_addr را روی "0.0.0.0:5000" و server_public_addr را روی "<IP_عمومی_سرور>:5000" بگذارید (سرور هنگام اجرا خودش پورت :5000 را با پورت داینامیک سرویس مثل 4433 جایگزین می‌کند).

بیلد سرور و اجرای سرویس:

Bash
cargo build --release -p moba_server
sudo ufw allow 4433/udp
sudo systemctl start moba-server@4433_1.service
روی سیستم لوکال خودتان (بیلد کلاینت با IP و پورت دلخواه):

در PowerShell:

PowerShell
$env:MOBA_SERVER_ADDR="<IP_عمومی_سرور>:4433"; cargo build --release -p moba_client
یا در CMD:

DOS
set MOBA_SERVER_ADDR=<IP_عمومی_سرور>:4433 && cargo build --release -p moba_client
بعد از بیلد، کافی است target\release\moba_client.exe را همراه با پوشه assets/ کنار هم بگذارید و با دابل‌کلیک اجرا کنید (بدون نیاز به ترمینال و بدون فایل .ron کنار .exe).







من در حال ساخت یک بازی آنلاین هستم. این بازی در سبک moba + shooter هست و دوربین بازی ایزومتریک هست. موتور بازی با bevy آخرین ورژن و سمت سرور هم با rust پیاده سازی شده است. معماری این بازی crate یا shared هست. یعنی تمام قوانین بازی در shared نوشته میشود تا از کدهای تکراری جلوگیری شود و کلاینت و سرور کاملا با هم سینک باشند. همچنین از معاری server authority پیروری میکند. یعنی تمام قوانین بازی در سرور مدیریت می شود و کلاینت فقط نمایش دهنده هست. حالا نیازمندی خودم رو کامل برات شرح میدم و ازت میخوام رفع کنی و سورس کد کامل رو بهم بدی. همچنین به هیچ وجه از مقادیر پیش فرض استفاده نکن و حتما از کانفیگ فایل استفاده کن. چون استفاده از اعداد پیش فرض باعث میشه باگ های پنهان پیش بیاد و متوجه نشویم. پس نگران کرش کردن برنامه نباش



حالا من یک رودخانه از شمال غرب تا جنوب شرق به صورت شکل نامنظم دارم که در داخل یک دره هست. من لبه های این دره را با مدل سه بعدی خودم پوشاندم. باگ اینجاست که وقتی لبه کوه میرم و میخوام خودم رو توی آب بندازم، کمی سقوط میکنه به سمت پایین و انگار روی یک سطح دیگه ای میفته. بعد از اونجا هم کمی میرم جلوتر و تازه سقوط میکنه توی آب. نباید به این صورت باشه و باید مستقیم توی آب سقوط کنه. همچنین من وقتی بازیکنی دکمه space رو میزنه و منجر به رفتن داخل آب میشه، انیمیشن run_to_dive رو اجرا میکنه. حالا میخوام اگر بازیکن توی آب سقوط کرد و دکمه space هم نزد، بازم این انیمیشن اجرا بشه. لطفا هر فایلی که تغییرات داره رو به صورت کامل بهم بده دانلود کنم
